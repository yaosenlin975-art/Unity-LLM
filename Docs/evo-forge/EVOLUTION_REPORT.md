## 抓出的假断言（我自己写错、自查没发现的）

最有价值的产出。12 条全部是对既有代码的错误描述，写进代码就是 bug：

1. `ContextPruning.SnipStaleToolResults` 并非"首次接入"，`LLMSession` 每轮已在调用；真死代码是 `ContextManager.PruneStaleLargeContent`。
2. "软阈值先 prune 就常走不到摘要"方向说反：折叠区不进 prompt 故不减少发送 token，但 `EstimateTotalTokens()` 累加全部 rounds，所以确实会推迟触发。
3. `LLMRequestLog.CacheHitTokens` 已存在且非流式已填，缺的只是日志窗口那一列。
4. `MonoRunner.Update` 不受 `Time.timeScale` 影响，只受 `isPaused` 整体跳过。
5. HARD 退出"必须补 `[Aborted]` 帧"没有消费方（该轮 tool 消息从不入历史也不再发请求）→ 按事实删除。
6. "现有 `[Tool]` 注册工具基本是查询"是假断言——全项目 `[Tool]` 标注数为 **0**。
7. 流式 usage 不在收尾 chunk，而是独立的 `choices: []` chunk（`isDone=false`），`[DONE]` 另发一条不带 token → 必须跨 chunk 缓存后在 `[DONE]` 落日志，否则"单测能过、真链路恒 0"。
8. `ToolRegistry.ToLLMTools()` 返回缓存的同一 List 实例，直接 `AddRange` 会污染注册表并让动作声明每轮重复累积。
9. 事实槽无法用 `AddContext()` 原位更新（只有 append / Clear）。
10. 墙钟默认 25s 与 `MaxToolRounds 5 × ActionTimeout 15s` 数学上不可能同时成立。
11. `BuildParameterSchema` 的入参写成 `RegisteredTool`（实为 `MethodInfo`），且它无跳过复杂类型的口子——照搬会造出假 `ctx` 参数。
12. 非幂等阈值定 2 时，"两轮各扣一次钱"照样发生（阈值必须恒 1）。
13. `say` 若留在 LoopGuard 签名里，模型换个措辞就绕开非幂等拦截——重复扣钱的洞被自己新加的功能重新打开。
14. 「锁等待超时计入 L2 计数」× 「非幂等配额按 session 累计」= 一次排队失败让该签名永久 `[Blocked]`，NPC 从此拒绝该玩家（两个规则各自正确，组合成死锁）。
15. 「长动作不计入墙钟」写成"挂独立 CTS"是无法实现的（CTS 不能暂停），必须写成额度累计扣减。
16. 墙钟自洽式漏算 `LockWaitSeconds`，默认配置（90 vs 3×(15+5+20)=120）违反自家断言。
17. `LockKey` 没说是字面量还是 args 模板，`item:{itemId}` 里的 `itemId` 无从取得；「禁止粗粒度键」是不可执行的口号，改成「键中必须含 `:`，否则注册期报错」。
18. 新加的 `SayTemplates` 复活了 ADR-007 明确拒绝的"按 actionId 覆盖表"，且 Unity SO 存不了 `Dictionary`；`UnmetPromiseLines` 与 `FallbackLines` 是两个重叠的台词池，墙钟路径会同时命中播两句话 → 都删，台词池只留一个。
19. ADR-011 让内核写 `LLMAgent/{sessionId}/history.json`，与既有 `ContextManager.ExportRoundsJson/ImportRoundsJson` 构成双通道，同一份数据两处写。

另有 4 类属于"没写就等于让实现者猜"的缺口：`[AgentAction]` 的 `ctx` 注入与 schema 排除、`AbortTurn` 置位后同批剩余 `tool_call` 的处置、`Stale`/失败轮的终止事件与历史写入、`sessionId` 与持久化 key 规范。

## 复现性问题的教训

- 第 3、9、11 轮的问题都是**前一轮修复本身**造成的（修 A 说错 B、改数值漏第 6 处引用）。"改完必须再审"不是形式，本循环里 3 次靠再审才发现自伤。
- 阈值/档位类规则一旦被分档（幂等 vs 非幂等 vs L3 插入），任何一处漏改就会留下互相打脸的残句；第 12–14 轮三连击全是这个模式。

## 教训补记（第 17 轮）

新机制本身没错，**接缝**才是问题：`say`（ADR-008）× LoopGuard 签名（ADR-004）、锁等待计数（ADR-010）× 非幂等配额（ADR-004）、长动作豁免（ADR-009）× 墙钟自洽式。三处都是"两条各自成立的规则交叉后产生死锁或洞"。以后每加一个机制，必须重跑一遍全部既有规则的组合，而不是只检查新机制自身。
