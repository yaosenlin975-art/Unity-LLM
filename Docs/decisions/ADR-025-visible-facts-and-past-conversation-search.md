# ADR-025: 全量可见事实不再提供列举与检索动作

## Status
Accepted

## Date
2026-09-22

## Context

`AgentCore.BuildInjection()` 每轮都把 `AgentMemory.RenderBlock()` 全量拼入 system 内容。现有 `list_facts` 返回同一文本，`search_memory` 又同时搜索事实、运行态轮次和压缩归档。前者不产生任何新信息；后者的事实命中还可能挤占真正需要召回的旧对话结果。与此同时，超过活动窗口的轮次和压缩归档原文并不在当前提示词中，仍需要显式检索入口。

事实由模型写入，可能错误、过期或被玩家纠正。因为事实会持续注入每一轮，只允许覆盖而不能删除会造成长期污染。

本 ADR 取代 ADR-005 中保留 `list_facts` 供模型自校正的决定，并收窄 ADR-020 中 `search_memory` 的检索范围。

## Decision

1. 删除模型可见的 `list_facts` 动作；调试器和 Inspector 继续直接读取 `AgentMemory.Facts`。
2. 将 `search_memory` 更名为 `search_past_conversation`，只搜索当前请求历史窗口之外的运行态轮次和本 session 压缩归档，不搜索已全量注入的事实。
3. 当前请求可见的活动轮次不参与搜索，避免模型用工具重复读取眼前内容。
4. 保留 `write_fact` 与 `forget_fact`。模型从每轮 system 注入中已经知道准确 key，可以直接更新或删除；成功后仍立即持久化。
5. 不提供旧工具名兼容别名。旧名只由模型临时生成，不是存档协议；保留别名只会继续消耗声明 token 并延长迁移期。

## Alternatives Considered

### 保留 `list_facts`，只在描述中注明通常不要调用

- 优点：不改变工具集合。
- 拒绝理由：工具始终返回当前提示词已有内容，描述约束不能消除 schema 成本和误调用。

### 保持 `search_memory` 名称与三源搜索

- 优点：无重命名改动。
- 拒绝理由：名称过宽，事实和可见历史会产生重复结果，并已出现模型换关键词反复搜索的问题。

### 删除 `forget_fact`，用 `write_fact` 空值表示删除

- 优点：少一个工具声明。
- 拒绝理由：空字符串可能是无效输入或真实值，混用会模糊写入与删除语义；错误事实又会持续污染每轮提示词。

### 彻底删除对话检索

- 优点：工具最少。
- 拒绝理由：压缩后当前上下文只剩摘要，旧原文仍有明确的按需召回需求。

## Consequences

- 正向：少一个无信息增益的工具声明，事实不再占据旧对话搜索结果。
- 正向：工具名称与数据边界一致，模型只在需要找回当前上下文不可见的旧对话时调用。
- 正向：事实纠错仍有明确的写入和删除操作。
- 负向：引用旧 `search_memory` 名称的测试、工具开关配置和提示词需要迁移；旧调用会明确返回工具不存在。
- 约束：事实继续全量注入时不得重新增加事实列举或事实搜索工具；只有未来改变事实注入策略时才能重新评估。
